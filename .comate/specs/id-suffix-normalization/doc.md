# ID 后缀清理（仅去掉最后一个 `_T数字` 段）

## 需求理解
你希望把测试用例 ID 中末尾的子序列号去掉：
- `TC012345_T1` -> `TC012345`
- `GEN_001_T11` -> `GEN_001`
并且当 ID 中有多个 `_` 时，只去掉最后一个 `_T数字` 段。

## 关键约束与风险判断
当前数据库表 `test_cases.id` 是主键（PK）。如果直接把数据库中的 `*_Tn` 批量改成基础 ID，会出现主键冲突（同一会话多轮会变成重复 ID）。这会导致数据写入失败或数据丢失风险。

因此本次采用“**业务 ID 规范化显示 + 内部唯一键保留**”方案：
- 对用户可见 ID（表格、筛选、执行入参）按规则去后缀。
- 内部持久化/数据库仍保留原唯一 ID，不破坏现有结构。

## 两套 ID 的作用（你关心的点）

为了同时满足“显示去后缀”和“系统仍可唯一定位记录”，这次会有两套字段：

1. `id`（业务显示ID）
- 给你在页面看到、筛选、分组用。
- 规则：去掉末尾 `_T数字`。
- 例如：`GEN_001_T11 -> GEN_001`。

2. `__raw_id`（内部唯一ID）
- 仅内部使用，不展示给业务。
- 保留数据库真实主键值（原始 ID，不去后缀）。
- 用于删除、移动、保存时精确定位，防止重复 `id` 造成误操作。

## 你提到的 session 分组逻辑是否满足

我核对了执行引擎当前逻辑：
- `app/test_engine.py:376-388` 按 `case.get("id")` 分组 multi-turn。

因此本方案会保证：
- 送入执行引擎的 `id` 使用“去后缀后的业务ID”。
- 同一个 session（例如 `GEN_001_T1/T2/T11`）会归并为同一组 `GEN_001`。
- 这正好满足你说的“同一个ID按同一个session处理”。

## 方案设计

### 1) 规范化规则（统一函数）
新增统一函数：
- 仅去掉末尾 `_T\d+`
- 其余 `_` 不处理

示意：
```python
re.sub(r"_T\d+$", "", case_id)
```

### 2) 数据加载阶段处理
在 `app/utils.py` 的 `load_data()` 中：
- 保留原始唯一 ID 到内部字段（例如 `__raw_id`）
- 对显示字段 `id` 应用规范化

这样 UI 显示满足你的要求，但底层仍可唯一定位。

### 3) 页面操作改用内部唯一键
在 `app/ui/testcases.py`：
- 删除、移动、保存、运行等操作，统一通过 `__raw_id` 或稳定 `__row_key` 回溯到原始记录
- 避免因显示 ID 重复导致误选、多选、漏选

### 4) JSON 写回策略
`save_data()` 前去掉内部字段（`__raw_id`, `__row_key`），保持现有数据结构兼容。
